# Phase 2: Usability

## Context

Phase 1(ノートCRUD+グラフ表示・リンク)はマージ済み(PR #1〜#4)。Phase 2の
ゴールは「機能として存在する」ことではなく、**主要な操作(作成・編集・配置・
接続・削除)を、説明なしで迷わず継続的に行える状態**にすること。見た目の
装飾ではなく操作性・理解しやすさを優先する(ユーザー確認済み)。

### 実機調査で発見した問題(headless Chromiumで実際に操作して確認)

1. **【最重要・構造的バグ】キャンバスとエディタの視覚的衝突**: ノートが増えて
   グラフキャンバスの内容(ノード配置)が固定高(400px)を超えると、overflowが
   クリップされず、下にあるノート編集フォーム(タイトル入力・本文欄)に
   ノードが重なって表示される。編集操作自体が困難になる
2. **ノート削除に取り消し手段がない**: 「削除」ボタンで確認なく即時削除され、
   元に戻せない。誤操作でのデータ消失リスクが高い
3. **空のノートが複数あると一覧で区別できない**: タイトル未入力のノートは
   すべて「(無題)」と表示され、どれがどれか分からない

### ユーザーとの確認で決定した対応方針

- **削除**: 確認ダイアログではなく、**直近1件の削除のみを元に戻せる単一ステップ
  Undo**を実装する。**これは将来の汎用的な操作履歴機能(編集・作成・リンクを
  含む履歴、分岐・探索等)の基盤としては位置づけない**。汎用履歴が必要になった
  時点で、その時の要件に応じてモデルを改めて設計する(先取りしない)
- **空ノートの区別**: 一覧に本文の先頭数文字をプレビュー表示する
- **レイアウト**: サイドバー(一覧)+ キャンバス(メイン)+ パネル(エディタ)の
  構成に再構成する(装飾目的ではなく、構造的な重なり不具合を根本解決するため)
- **E2E導入**: Playwrightを正式にプロジェクトへ導入する。実行はアプリの
  Dockerイメージに統合せず、別CI jobとして分離する(アプリ本体のイメージは
  肥大化させない)
- **DevSecOps導入**: 依存脆弱性監査(`pnpm audit`)、Dependabotによる依存更新PR
  自動化、Gitleaksによるシークレットスキャンを導入する。静的解析(CodeQL等)は
  現時点の規模ではYAGNIと判断し見送る

## Recommended Plan

実装順序: 先にCI/検証基盤(DevSecOps→E2E)を整え、その後UXのFeature 003〜005を
実装する。各FeatureのPRでE2Eスイートを実際の改善内容に合わせて拡張していく。

### Chore A: DevSecOps CI追加

**Scope**

- `pnpm run verify` に `pnpm audit --audit-level=high` のステップを追加する
  (ローカル・Docker・CIで同一コマンドという既存方針を維持するため、専用の
  CIステップではなくverifyスクリプト自体に組み込む)
- `.github/dependabot.yml` を追加(npm/pnpmエコシステム、Dockerfileのベース
  イメージ、GitHub Actions自体の3エコシステムを対象に週次スケジュール)
- CI(`ci.yml`)に `gitleaks/gitleaks-action` を使った軽量な `secrets-scan` job
  を追加する(既存の `verify` jobとは独立させ、関心を分離する)

**Out of Scope**

- CodeQL等のSAST導入(見送り、必要になった時点で再検討)
- 脆弱性の自動修正・自動マージ

### Chore B: E2E基盤導入(Playwright)

**Scope**

- `@playwright/test` を devDependency として追加
- `playwright.config.ts`: `testDir` を `tests/e2e`、`baseURL` を
  `http://localhost:3000` に設定。**Playwright自身にアプリを起動させる
  (`webServer`オプション)は使わない** — 「Dockerがアプリ実行の唯一の正規手段」
  という既存方針に合わせ、E2E実行前に `docker compose up -d` で起動済みの
  アプリに対してテストする前提とする
- `package.json` に `"test:e2e": "playwright test"` を追加。**`pnpm run verify`
  には含めない**(ユーザー選択の「別CI job」方針に合わせ、verifyは現状の
  範囲・速度を維持する)
- テストファイルは `tests/e2e/*.spec.ts`(Vitestの `tests/lib/*.test.ts` とは
  ディレクトリ・拡張子で分離し、互いのテストランナーが誤って拾わないようにする)
- 最初のE2Eとして、Phase 1で手動検証していた最小シナリオ(ノートを2件作成→
  ドラッグで接続→Edgeが画面に表示される)を自動テスト化する
- CI(`ci.yml`)に `e2e` jobを追加: `docker compose up -d` でアプリを起動し、
  公式Playwrightイメージ(`mcr.microsoft.com/playwright`、`@playwright/test`と
  同一バージョンを指定)をコンテナとして実行してテストする。アプリ本体の
  Dockerfileにはブラウザ関連の依存を一切追加しない

**Out of Scope**

- 複数ブラウザでのマトリクステスト(Chromiumのみ)
- CIキャッシュ最適化(既存方針通り必要最小限に留める)
- UIコンポーネント単体テスト(React Testing Library)の導入(引き続き見送り)

### Feature 003: レイアウト再構成(サイドバー + キャンバス + パネル)

**Scope**

- ページ全体をビューポート高に収まるレイアウトに変更する: 左に固定幅の
  サイドバー(ノート一覧、縦スクロール可)、中央にグラフキャンバス(残り幅・
  残り高さいっぱいに拡張、`overflow`を正しく処理してノードが他要素に
  はみ出さないようにする)、選択中ノートがある時のみ右側に固定幅の編集
  パネルを表示する(現状の条件表示は維持)
- `NoteGraph` の高さを固定値(400px)ではなく親要素いっぱい(`height: 100%`)に変更
- ノート追加時にキャンバスが新しいノードも見える範囲になるよう、ノート数が
  変わるたびに再フィットする
- 副次的に: 選択中のノート(一覧の項目・グラフのノード)を視覚的に区別する
  最小限のスタイル(背景色や枠線)を付与する。空状態(ノート0件)のキャンバスに
  一行だけ案内文を表示する(「初見で何をするアプリか分かる」ことが目的)

**Out of Scope**

- モバイル/狭幅レスポンシブ対応、パネルのリサイズ・折りたたみ、装飾目的の
  デザイン(配色・アイコン等)

**受け入れ基準(「説明なしで継続操作できる」観点)**

- ノートを8件程度作成しても、グラフノードがエディタパネルや一覧に重ならない
- 選択中のノートが一覧・グラフの両方で見た目上わかる
- ノートが0件の状態で、何をすればよいか画面内の文言だけで分かる

**E2E**: Chore Bで作成した接続シナリオに、複数ノート作成後の重なり無し確認を追加

### Feature 004: 空ノートの識別性向上(一覧プレビュー表示)

**Scope**

- `NoteList` の各項目のラベルを「タイトルが空なら本文の先頭N文字(例: 20文字)+
  省略記号、それも空なら『(無題)』」というルールに変更する
- グラフノードのラベル(`NoteGraph`)も一覧と同じルールに統一する
- 純粋なフォーマット関数(例: `formatNoteLabel(note): string`)を `src/lib/notes.ts`
  に追加し、Vitestで検証する(タイトルあり/タイトルなし+本文あり/両方空、の
  3パターン)

**Out of Scope**

- Markdownやリッチな本文プレビュー、一覧の並び替え・検索・フィルタ

**受け入れ基準**: タイトル未入力で本文が異なる複数ノートが、一覧上で区別できる

### Feature 005: ノート削除のUndo(元に戻す)

**Scope**

- ノート削除時、削除された `Note` と、カスケード削除された `Edge[]` を
  直近1件分だけ一時的に保持する(単一スロット。新たな削除で上書きされる)
- 削除直後に軽量な通知(「ノートを削除しました」+「元に戻す」ボタン)を表示し、
  クリックすると削除前の状態(ノート・関連Edgeとも)を復元する
- 復元は状態管理層(`page.tsx`)で直接ノート・Edgeを配列に戻す形で行い、
  `notes.ts`/`edges.ts` に新しいドメイン関数は追加しない
- Undo情報はメモリ上のみ、単一スロットのみ保持する。**汎用的な操作履歴
  (Undo/Redoスタック、他操作への拡張)を見据えた設計は行わない**

**Out of Scope**

- 複数手のUndo/Redo、作成・編集・リンク操作のUndo、Undo情報の永続化

**受け入れ基準**: ノートを削除した直後に「元に戻す」を押すと、削除前の状態
(ノート・接続していたEdgeとも)に戻る

**E2E**: 削除→Undo通知の表示→クリックで復元、の一連をテスト化する

## Alternatives Considered

- **削除に確認ダイアログを追加**: シンプルだが操作を止めてしまう。ユーザーが
  「履歴を残して戻せる方式」を明示的に選んだためUndo方式を採用
- **削除Undoを汎用履歴機能の第一歩として設計**: 将来の分岐・探索型履歴を
  見据えた抽象化は、現時点では要件が定まっておらず過剰設計になるため、
  ユーザー指示により明確に対象外とした
- **キャンバスのoverflowを隠すだけの最小修正**: 手軽だがノートが増えた時の
  根本的な使いにくさは解決しない。ユーザーがサイドバー+キャンバス+パネルへの
  再構成を選択したため不採用
- **E2Eをアプリ本体のDockerイメージに統合**: 単一コマンドで完結する利点は
  あるが、イメージ肥大化とビルド時間増を招く。ユーザーが別CI job方式を
  選択したため不採用
- **CodeQL等のSAST導入**: 現状の規模ではYAGNIと判断し見送り、DevSecOpsの
  第一歩は監査・Dependabot・シークレットスキャンに限定した

## Definition of Done

1. `specs/features/003-layout-restructure.md`, `004-note-label-preview.md`,
   `005-delete-undo.md` が記録されている(Chore A/BはFeature specとしてでは
   なく `specs/architecture.md` と `docs/plan/phase-2-usability.md` に記録する)
2. `pnpm run verify`(`pnpm audit`を含む)がローカル・Docker双方で成功する
3. CI上で `verify` `secrets-scan` `e2e` の3 jobが成功する
4. E2E(Playwright)で以下がテスト化され成功する: ノート接続、複数ノート時の
   レイアウト非重複、削除→Undoによる復元
5. Vitestで `formatNoteLabel` 相当の関数のテストが追加され成功する
6. `specs/architecture.md` に、E2Eの実行アーキテクチャ(アプリはDocker、
   Playwrightは別ランナー)、DevSecOpsの導入内容、削除Undoが汎用履歴の
   基盤ではないことが明記されている
7. 各Chore/FeatureごとにトピックブランチChore→PRが作成されている(マージはしない)
8. DB・永続化・認証・AI機能に関する実装が一切含まれていない
